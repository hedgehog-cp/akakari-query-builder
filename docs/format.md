# 入出力フォーマット

本アプリが扱うクエリの入出力形式は、いずれも JSON である。
HJSON 独自の記法は出力せず、入力としても受理しない。
本ドキュメントはその入出力の形式を記述する。
記述対象は `src/serialize/json.ts` および `src/parse/json.ts` の現行実装であり、logbook 側の受理範囲の仕様ではない。

## 1. 概要

出力は `serializeQuery` が `JSON.stringify(値, null, 2)` で生成する。
生成物は厳密な JSON であり、HJSON は JSON の上位互換であるため、そのまま logbook に貼付できる。

入力は `parseQuery` が `JSON.parse` で解析する。
コメント、引用符なしのキー、末尾カンマなど JSON に含まれない HJSON の記法は受理せず、構文エラーとなる。

ダウンロード時のファイル名は `akakari-query.json` である(QUERY タブは `akakari-query-where.txt`)。
読み込みは `.json` に加えて `.hjson` も選択できるが、これは以前の版が `.hjson` で保存していたためであり、受理するのは JSON として妥当なテキストのみである。
構文エラーの場合は編集内容を保持しエラー表示のみを行う。
解析できたが読み飛ばした箇所は警告として画面上部に表示する。
警告の型は `ParseWarning` である。

## 2. 出力例

出力全体の形を以下に示す。
各節の記述はこの例の一部に対応する。

```json
{
  "種別": "赤仮砲撃戦",
  "日時": { "開始": "20240720000000" },
  "出力": {
    "AND": [
      { "攻撃艦": "自軍" },
      { "ダメージ": { "より大きい": 0 } },
      {
        "OR": [
          { "攻撃艦.装備1.名前": { "含む": "電探" } },
          { "攻撃艦.装備2.名前": { "含む": "電探" } },
          { "攻撃艦.装備3.名前": { "含む": "電探" } },
          { "攻撃艦.装備4.名前": { "含む": "電探" } },
          { "攻撃艦.装備5.名前": { "含む": "電探" } },
          { "攻撃艦.装備6.名前": { "含む": "電探" } }
        ]
      }
    ]
  },
  "攻撃艦装備": {
    "装備数": { "以上": 2 },
    "条件": { "装備カテゴリ": "小型電探" }
  }
}
```

`出力` の OR は、GUI 上では攻撃艦のいずれかのスロットに対する1個の装備スロット条件であり、第5節に示す規則で展開したものである。

## 3. トップレベル

| キー                      | 出力条件                             | 入力での受理                             |
| ------------------------- | ------------------------------------ | ---------------------------------------- |
| `種別`                    | 常に出力                             | 欠落・未知の値は警告し、砲撃戦として扱う |
| `日時`                    | 期間が1件のときマップ、2件以上で配列 | マップおよび配列                         |
| `出力`                    | 出力条件が存在するとき               | マップおよび配列(配列は OR)              |
| `攻撃艦装備` `防御艦装備` | 装備条件が存在するとき               | マップおよび配列(配列は OR)              |

`種別` の値は `赤仮砲撃戦`、`赤仮雷撃戦`、`赤仮夜戦` のいずれかである。
出力時のキー順は上表の順である。
値を持たないキーは出力しない。

## 4. 値の条件

列または装備属性に与える条件を指す。

| 条件       | 出力                                                                | 入力での受理                          |
| ---------- | ------------------------------------------------------------------- | ------------------------------------- |
| 一致(1件)  | 直値。例 `"自軍"`                                                   | 直値、1要素の配列、`{"一致": 値}`     |
| 一致(複数) | 配列。例 `["自軍", "敵軍"]`                                         | 配列、`{"一致": [...]}`               |
| 部分一致   | `{"含む": "電探"}`                                                  | 同左。配列指定も可                    |
| 正規表現   | `{"正規表現": "^[0-9]+$"}`                                          | 同左。配列指定も可                    |
| 数値比較   | `{"以上": 2}` `{"より大きい": 0}` `{"以下": 5}` `{"より小さい": 5}` | 同左。値が数値でなければ警告し破棄    |
| 論理積     | `{"AND": [...]}`                                                    | 同左。配列以外は警告し1要素として解釈 |
| 論理和     | `{"OR": [...]}`                                                     | 同左。配列以外は警告し1要素として解釈 |
| 否定       | `{"NOT": 条件}`                                                     | 同左                                  |

`含む` および `正規表現` の値は入力時に文字列化する。
`{"含む": 12}` は `"12"` として解釈される。
出力が生成するマップのキーは常に1個であるのに対し、入力は複数キーを持つマップを AND として解釈するため、`{"以上": 1, "以下": 3}` は範囲指定となる。
未知のキーは警告し破棄する。

## 5. 出力節

列条件は `{"列名": 値の条件}` の形式をとる。
入力時、列名は選択中の戦闘種別の列カタログと照合し、
存在しない列は警告し破棄する。
グループは `AND`、`OR`、`NOT` の各キーで表す。

GUI の装備スロット条件および表示装備条件は、そのままの形では出力しない。
`src/model/expand.ts` の `expandOutput` が CSV の列条件へ展開する。
展開規則を以下に示す。

| GUI 上の指定       | 展開結果                              |
| ------------------ | ------------------------------------- |
| いずれかのスロット | 装備1〜装備6の OR                     |
| すべてのスロット   | 装備1〜装備6の AND                    |
| N個以上            | 6個からN個を選ぶ全組み合わせの OR     |
| どれも満たさない   | 装備1〜装備6の OR を NOT で包んだもの |
| 表示装備           | 表示装備1〜表示装備3の OR または AND  |

入力時は `src/model/fold.ts` の `foldOutput` が逆変換を試みる。
成立するのは全スロットが過不足なく揃い、各枝の条件が一致する場合に限る。
枝ごとに条件が異なる木や枝を削除した木は、列条件のまま GUI に表示される。
本アプリの出力をそのまま入力した場合は必ず成立する。

## 6. 装備節

`攻撃艦装備` および `防御艦装備` は装備の個数に対する条件であり、`装備数` と `条件` の対で表す。

```json
{
  "装備数": { "以上": 2 },
  "条件": { "装備カテゴリ": "小型電探" }
}
```

一方のキーのみでは logbook 側で条件が登録されないため、出力は常に対で行い、入力時に一方のみの場合は警告し破棄する。
`条件` は `{"属性": 値の条件}` の形式をとる。
属性は `src/model/types.ts` の `ITEM_ATTRS` に定義した17種である。
値に `null` を指定した場合は装備の存在のみを条件とする。
`AND`、`OR`、`NOT` による入れ子を許す。

## 7. 日時

期間は `{"開始": "20240720000000", "終了": "20250101000000"}` の形式で表す。
値は `yyyyMMddHHmmss` の14桁固定である。
未指定の側はキーごと出力しない。
入力時、桁数が異なる値は警告し破棄する。
開始と終了の双方が読めない場合はその期間を破棄する。
期間が2件以上のときは配列で表し、期間相互の関係は OR である。

## 8. 往復時の差異

出力したテキストを再入力した場合、および手書きの JSON を入力した場合に生じる差異を以下に示す。

| 対象                  | 挙動                                                                                                                                                                                               |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `一致`                | 入力では受理するが、出力では使用しない                                                                                                                                                             |
| 1要素の配列           | 次回出力時に直値へ変換される                                                                                                                                                                       |
| 空配列 `[]`           | 入力時に警告なく条件ごと破棄する。値が未入力の一致は `[]` として出力されるため、往復により条件が1件減る                                                                                            |
| 空マップ `{}`(出力節) | 条件なし(null)ではなく、子を持たないグループとして保持する                                                                                                                                         |
| 空マップ `{}`(日時)   | 開始も終了も読めないため警告なく破棄する                                                                                                                                                           |
| 装備節の未知キー      | 警告なく破棄する。値の条件および出力節では警告を出力する                                                                                                                                           |
| 種別と列カタログ      | 列の照合には読み込み直前に選択されていた種別のカタログを使用する。異なる種別のファイルを読み込むと、当該種別にのみ存在する列が警告とともに破棄される。再度同じテキストを読み込めば正しく解釈される |
| 装備スロット条件      | 展開して出力するため、逆変換が成立する形でなければ列条件のまま表示される                                                                                                                           |

## 9. 参照実装

- 出力: `src/serialize/json.ts`
- 入力: `src/parse/json.ts`
- 装備スロット条件の展開: `src/model/expand.ts`
- 展開結果の逆変換: `src/model/fold.ts`
- クエリの型定義: `src/model/types.ts`

QUERY 関数の WHERE 句への変換は `src/serialize/gquery.ts` が行う。
JSON 形式ではないため本ドキュメントの対象外とする。
